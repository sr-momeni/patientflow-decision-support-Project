# Patient Flow Decision Support System (Full Documentation)

This document provides a comprehensive breakdown of every file and directory in this project. The system is a multi-layered application combining machine learning, discrete-event simulation, and a full-stack hospital management platform.

---

## 📂 Root Directory
*   **`Chatbot`**: Entry point or utility script for the chatbot interface.
*   **`advanced_analysis.py`**: A powerful metrics engine that parses `simulation_events.log`. It calculates:
    *   Reservation Accuracy (Successful Catches vs. Expired Holds).
    *   Bed Occupancy Rate comparison (FCFS vs. AI).
    *   "Opportunity Cost" (Total wasted bed-minutes from false-positive reservations).
    *   Generates `reservation_pie.png` and `bed_time_bar.png`.
*   **`visualize_comparison.py`**: Generates high-level statistical reports comparing wait times and LOS across all urgency levels. Outputs `comparison_plot.png`.
*   **`patient_arrival_analysis.py`**: Statistical analyzer for raw arrival data. Helps verify if the synthetic generator is accurately mimicking national triage distributions.
*   **`convert_data.py`**: Data transformation utility. It converts backend simulation CSVs into the specific JSON/Array format required by the `frontend/script.js` for timeline rendering.
*   **`debug_analysis.py`**: A lightweight script for troubleshooting simulation logs and identifying malformed events.
*   **`requirements.txt`**: Project dependencies (FastAPI, Scikit-learn, Pandas, Seaborn, etc.).
*   **`pytest.ini`**: Configuration for automated backend testing.
*   **`openAI_key.txt`**: Secret storage for the Chatbot LLM integration (if enabled).

## ⚙️ Backend Module (`/backend`)
The core logic of the system, implementing both the API server and the Simulation engines.

### 🏛️ Architecture & Infrastructure
*   **`main.py`**: The primary CLI runner. Allows users to "exercise" a specific scenario (e.g., `icu_bottleneck`) and see top-level utilization results.
*   **`server.py`**: The central **FastAPI** application.
    *   Endpoints for patient signup, login, and triage submission.
    *   Mounts the simulation dashboard at `/simulation`.
    *   Mounts the eHospital React app at `/`.
*   **`database.py`**: SQLAlchemy-based persistence layer. Manages the MySQL/SQLite connection for storing user credentials and triage history.

### 🤖 Agents (`/backend/agents`)
*   **`urgency_scoring_agent.py`**: Uses NLP or rule-based logic to map patient symptoms (from triage) to CTAS Urgency Levels (1–5).
*   **`resource_allocation_agent.py`**: Heuristic engine that recommends specific beds based on acuity and current availability.
*   **`test_triage.py`**: Unit tests for the scoring logic.

### 💬 Chatbot (`/backend/chatbot`)
*   **`chatbot_agent.py`**: Manages the conversational flow with a patient, collecting symptoms and feeding them to the urgency scorer.
*   **`chatbot_routes.py`**: REST API endpoints for the chatbot frontend to communicate with the AI agent.

### 🧠 ML & Prediction (`/backend/ml`)
*   **`predictor.py`**: The `HighUrgencyPredictor` class. Uses a `HistGradientBoostingRegressor` to forecast arrival counts.
*   **`train_model.py`**: Pipeline to train and save the model to `/models`.

### 🧪 Simulation Core (`/backend/simulation`)
*   **`predictive_engine.py`**: Discrete Event Simulation (DES) featuring dynamic priority queuing and Priority Aging.
*   **`engine.py`**: Standard FCFS simulation logic.
*   **`event_model.py`**: Data structures defining `SimulationPatient`, `HospitalState`, and `BedAssignment`.
*   **`run_predictive.py` / `run_fcfs.py`**: Scripts to execute batch simulations on large datasets.

### 📈 Optimization & Scenarios (`/backend/optimization`)
*   **`evaluate_agent.py`**: The master testing suite for Threshold/Duration sweeps and Scenario benchmarking.
*   **`congestion_scenarios.py`**: Configurations for 6 operational environments (Normal, Severe, Burst, etc.).
*   **`allocation_rules.py`**: The logic defining which patient symptoms necessitate an ICU bed vs. an ED bed.
*   **`constraints.py`**: Logic for resource limits (Physicians, Nurses, Lab slots).

### 🏥 Static Hospital (`/backend/static_ehospital`)
*   Contains the production-ready build of the **eHospital React Frontend**.
*   `index.html`, `assets/`, `images/`, and PDF documentation for the hospital's internal operating procedures.

---

## 🖥️ Frontend Module (`/frontend`)
The "Simulation Dashboard" that visualizes the AI's impact.

*   **`index.html`**: Dashboard layout with occupancy gauges, wait-time panels, and a Gantt chart container.
*   **`script.js`**: Massive UI engine.
    *   Handles timeline zooming/panning.
    *   Calculates average wait times from simulation data on-the-fly.
    *   Renders patient "lane" assignments in the Gantt chart.
*   **`data_predictive.js` / `data_fcfs.js`**: Transformed data payloads generated by `convert_data.py`.

---

## 📊 Data & Assets
*   **`/data/raw/`**: Source CSVs from the `synthetic_generator.py`.
*   **`/data/plots/`**: Visual evidence generated by the evaluation suite (pie charts, line graphs).
*   **`/models/`**: Stores the binary trained model file (`.pkl`).
*   **`/backend/legacy_v1/`**: An archive of the initial project version before the Priority Aging and DES overhaul.
